# RAG System Improvements Plan

This document outlines the bugs identified in the current RAG implementation and the proposed solutions.

## 1. Relevance Grading Logic Flaw

**Issue:** In `src/controllers/WorkflowController.py`, the `grade_relevance` method tries to parse the LLM output to determine if the retrieved context is relevant. It uses:

```python
if "IRRELEVANT" in grade or "NO" in grade:
    return False
return "RELEVANT" in grade or "AMBIGUOUS" in grade or "YES" in grade
```

If the LLM outputs `"NOT RELEVANT"`, the first condition is `False` (because `"IRRELEVANT"` is not in it, and `"NO"` is not either). Then it falls through to the second condition, which is `True` (because `"RELEVANT"` is a substring of `"NOT RELEVANT"`).
**Solution:** Change the logic to exact matching or regex with word boundaries. Since we only expect a single word out of `RELEVANT, AMBIGUOUS, or IRRELEVANT`, it's safer to extract words using regex and check if the _exact_ word exists.

## 2. Empty Context Handling

**Issue:** If `context_string` ends up empty in `_prepare_chat_context` (e.g. if the DB has no context and fallback failed), it just warns: `WARNING: NO CONTEXT RETRIEVED FROM DATABASE!`. Then it proceeds to call the RAG system prompt with an empty context. This can confuse the LLM or cause hallucination.
**Solution:** Add a default empty state string (e.g., `No relevant context could be found`) to provide clear instructions to the LLM when context is missing, so it doesn't try to answer out of domain.

## 3. Missing Unit Tests

**Issue:** The project currently lacks tests covering the `WorkflowController` string matching logic.
**Solution:** Create `src/tests/test_workflow_controller.py` with pytest to explicitly test the `grade_relevance` method with various LLM outputs (like `"NOT RELEVANT"`, `"IRRELEVANT"`, `"RELEVANT"`, `"AMBIGUOUS"`).

## 4. Unsafe Python Execution

**Issue:** In `ToolManager.execute_python`, the execution environment is somewhat restricted but lacks a timeout. A while loop `while True: pass` generated by the LLM would freeze the server.
**Solution:** Add a basic timeout mechanism, potentially running the `exec` in a thread with a timeout limit to avoid blocking the asyncio event loop indefinitely.
